# GPT Image 2.5 Agent Kit

[English](README.md)

Локальный набор инструментов для генерации и редактирования изображений через GPT Image 2.5. Он помогает агенту или человеку собрать запрос, назначить роли референсам, проверить план до отправки, получить изображение и сохранить технический отчёт о выполнении.

Проект работает из командной строки. Это не веб-сервис, не графический редактор и не официальный клиент OpenAI.

## Что получает пользователь

На вход можно передать:

- текстовое описание изображения;
- фотографии человека, образцы стиля, логотипы и макеты;
- исходное изображение для редактирования;
- маску области, которую можно изменить;
- требования к формату, размеру, фону и качеству.

На выходе проект создаёт:

- проверенный файл PNG, JPEG или WebP;
- по запросу - технический JSON-отчёт (receipt) с выбранной моделью, параметрами, хешами референсов и фактическими свойствами результата;
- в режиме dry-run - только план будущего запроса, без сети и расхода лимита.

```text
Описание + референсы + настройки
                ↓
      сборка и проверка запроса
                ↓
       dry-run для просмотра плана
                ↓
   GPT Image 2.5 Sunburst или Flare
                ↓
  проверка завершения и декодирование файла
                ↓
       изображение + отчёт по запросу
```

## Из чего состоит продукт

| Часть | Что делает |
| --- | --- |
| `gpt-image25-agent` | Главная команда. Принимает запрос и параметры, запускает dry-run или реальную генерацию. |
| Пресеты | Добавляют готовые правила для портрета, продукта, превью, точного русского текста и других типовых задач. |
| Референсы и роли | Объясняют модели, для чего нужен каждый файл: лицо, стиль, логотип, макет или общий ориентир. |
| Identity/style-наборы | Сохраняют локальные наборы референсов и правил, чтобы использовать их повторно. |
| Редактирование и маски | Передают исходное изображение, список изменений и то, что требуется сохранить. |
| Валидатор | Проверяет пути, форматы, размеры, маски и целостность изображений до отправки и после получения. |
| Клиент backend | Отправляет подготовленный запрос в экспериментальный ChatGPT/Codex backend. |
| Receipt | Фиксирует параметры запроса и свойства результата без токена и без изображения внутри JSON. |

Код разделён по тем же обязанностям в пакете `src/gpt_image25_agent/`: CLI, авторизация, модели, промпты, работа с файлами, библиотека identity/style, клиент backend и receipts.

## Sunburst и Flare

В рабочем маршруте разрешены только две модели:

- `gpt-image-2.5-sunburst` - модель по умолчанию. Подходит для финальных изображений, точного редактирования и работы с референсами;
- `gpt-image-2.5-flare` - выбирается явно для более быстрой повседневной генерации.

Старая GPT Image 2 не включается автоматически при ошибке. Неизвестная или устаревшая модель будет отклонена до запроса.

`--host-model` и `--image-model` - разные параметры. Host model формирует вызов инструмента, а image model создаёт или редактирует изображение.

## Установка

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/AlekseiUL/gpt-image-2-5-agent-kit.git
cd gpt-image-2-5-agent-kit
python -m pip install -e .
gpt-image25-agent --help
```

После установки сначала запустите dry-run. Он используется по умолчанию, не обращается к токену, не делает сетевой запрос и не создаёт изображение.

Запускайте команды из каталога проекта или своей рабочей папки. Относительные пути считаются от текущего каталога, а `--root` задаёт разрешённую границу для чтения и записи файлов.

```bash
gpt-image25-agent "Предметная фотография белых наушников на сером фоне, без текста" \
  --quality high --aspect landscape \
  --dry-run --review-markdown
```

Проверьте модель, итоговый промпт, роли референсов, формат и путь сохранения. Для реальной генерации добавьте `--live` и настройте совместимый способ авторизации.

## Три рабочих сценария

### 1. Быстрый черновик через Flare

```bash
gpt-image25-agent "Минималистичная иллюстрация приморского города, без текста" \
  --image-model gpt-image-2.5-flare \
  --quality low --aspect landscape \
  --output-format jpeg --output-compression 85 \
  --out generated/coast.jpg --dry-run --json
```

После проверки плана замените `--dry-run` на `--live`.

### 2. Изображение по референсам

Каждому явному референсу назначается своя роль в том же порядке:

```bash
gpt-image25-agent \
  "Портрет: лицо взять из первого файла, свет и цвет - из второго" \
  --ref refs/person.png --ref-role identity \
  --ref refs/light.png --ref-role style \
  --preset likeness --quality high \
  --dry-run --review-markdown
```

Роль помогает сформулировать запрос, но не гарантирует точное сходство. Итоговое изображение нужно оценивать визуально.

### 3. Локальное редактирование

```bash
gpt-image25-agent \
  --edit-image generated/source.png \
  --mask refs/sign-mask.png \
  --edit 'Заменить надпись на вывеске точно на "ЧАСТЬ 4"' \
  --preserve "человека, ракурс и освещение" \
  --preserve "весь текст за пределами вывески" \
  --quality high --out generated/sign-edit.png \
  --dry-run --review-markdown
```

Маска должна быть PNG с альфа-каналом и совпадать по размеру с исходным PNG. Прозрачные пиксели отмечают область редактирования. Маска направляет модель, но не является пиксельной гарантией.

## Identity и style-наборы

Identity-набор хранит изображения человека или объекта. Style-набор хранит визуальные референсы, текстовое описание стиля и выбранные пресеты.

```bash
gpt-image25-agent --root . --add-identity me \
  --ref refs/me-front.png --ref refs/me-side.png

gpt-image25-agent --root . --add-style graphite \
  --style-prompt "графитовая палитра, тёплый свет, мало деталей" \
  --style-preset brand-style --ref refs/style.png
```

Повторное использование:

```bash
gpt-image25-agent "Портрет в студии" \
  --identity me --style graphite \
  --dry-run --review-markdown
```

Паки сохраняются локально в `.gpt-image2-agent/`. Название каталога оставлено для совместимости со старыми сохранёнными данными и не включает старую модель.

## Реальный запрос и авторизация

Live-режим отправляет итоговый промпт, выбранные референсы и маску во внешний backend. Используйте только те файлы, которые можно загружать для этой задачи.

Пример с токеном из переменной окружения:

```bash
export CHATGPT_CODEX_ACCESS_TOKEN="..."

gpt-image25-agent "Обложка без текста" \
  --live --auth-provider env \
  --quality high \
  --out generated/cover.png \
  --receipt generated/cover.receipt.json
```

Токен не записывается в receipt. Сам prompt по умолчанию тоже не сохраняется: вместо него записывается SHA-256. Полный prompt попадёт в receipt только при явном `--include-prompt-in-receipt`.

## Что проект проверяет

До запроса:

- разрешённую модель и сочетание параметров;
- существование и целостность референсов;
- формат и размеры маски;
- безопасные пути внутри `--root`;
- отсутствие случайной перезаписи файла.

После ответа:

- успешное завершение запроса;
- наличие полного финального изображения;
- декодирование файла как изображения;
- соответствие фактического и запрошенного формата;
- атомарную запись результата.

Повреждённый файл, незавершённый поток ответа или ответ с ошибкой не считаются успешным результатом. Автоматических повторов и скрытого переключения на другую модель нет.

## Важные ограничения

- Используется экспериментальный ChatGPT/Codex backend. Официальный OpenAI Images API и Responses API не реализованы.
- Наличие модели в официальной документации OpenAI не гарантирует доступ через конкретную подписку или backend.
- Локальная проверка параметров не доказывает, что backend примет каждую комбинацию.
- Запрошенный размер и фактический размер файла могут отличаться. Receipt хранит оба значения.
- Референсы и маски направляют модель, но не гарантируют точного сходства или неизменности пикселей.
- Проект создаёт одно финальное изображение за один live-запуск.
- Это локальный инструмент одного оператора, а не готовый многопользовательский сервис.

## Безопасная последовательность

1. Положите prompt, референсы и исходные изображения внутрь выбранного `--root`.
2. Запустите dry-run и проверьте план.
3. Убедитесь, что у файлов правильные роли и что в prompt нет лишних приватных данных.
4. Добавьте `--live` только для разрешённой реальной генерации.
5. После завершения откройте итоговый файл и проверьте содержание, текст, сходство и композицию.
6. Перед публикацией просмотрите receipt: пути, хеши и названия паков тоже могут раскрывать контекст.
