# Security model

This project is a local agent toolkit. It assumes the operator controls the machine and the files under `--root`.

## Default safety boundaries

- Dry-run is default unless `--live` is passed.
- Output files must stay under `--root` unless `--allow-output-outside-root` is passed.
- Reference images must stay under `--root` unless `--allow-ref-outside-root` is passed.
- Prompt files and receipts are also root-bounded by default.
- Output symlinks are refused.
- Parent symlink escapes are blocked by resolved-path checks.
- Generated bytes must look like PNG before writing.
- Reference files must have an allowed extension and valid image magic bytes.

## Identity/style packs

Saved identity and style packs live under:

```text
.gpt-image2-agent/
  identities/
  styles/
```

These are local memory for an agent. They can contain private face or brand references. Do not commit them unless they are intentionally public fixtures.

## Live mode

Live mode sends the final prompt and selected reference images to the configured backend. This may include face references or style boards. Use only with material you have the right to upload.

## Token handling

Supported token providers:

- env variable;
- explicit file;
- trusted local command executed without shell.

The tool redacts common token patterns in errors, but do not log or paste credentials.

## Not a service boundary

This CLI is not a multi-user service. If you build a web service on top of it, you need separate controls for authentication, per-user storage, consent, retention, abuse prevention and rate limiting.
